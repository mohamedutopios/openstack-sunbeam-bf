Identité · bonne pratique de production

Un découpage standard : domaines, projets, rôles, groupes, comptes

# la même chose en commandes (plateforme, admin_domain)
openstack domain create acme ; openstack project create acme --domain acme
openstack project create acme-prod --domain acme --parent acme --tag env:prod
openstack group create acme-ops --domain acme
openstack role add --group acme-ops --group-domain acme \
  --project acme-prod --project-domain acme member
openstack role add --group acme-audit --group-domain acme --domain acme --inherited reader
openstack role assignment list --user alice --user-domain acme --names --effective
ObjetRègle de production
DomaineUn par organisation (client, filiale, direction) : espace de noms, délégation et source d'identité propres. admin_domain pour la plateforme, service_domain intouché, Default vide.
ProjetUn projet racine par domaine, sans ressource, puis un projet par environnement (prod, preprod, dev), ou par application si l'équipe est grande. Quotas et tags env: sur chaque feuille.
RôleLes quatre rôles standards suffisent : reader (audit), member (exploite), manager (gère le domaine), admin (plateforme seulement). Rôle propre uniquement s'il implique un standard.
GroupeTout droit passe par un groupe : <org>-<fonction>. Un utilisateur n'a jamais d'affectation directe ; entrer ou sortir d'une équipe, c'est changer de groupe (dans l'annuaire).
UtilisateurVient de l'annuaire ou du SSO du domaine ; pas de compte local sauf secours. Nom unique dans son domaine : toujours --domain.
AdminJamais admin à un locataire, même sur un projet : avec les règles par défaut, admin quelque part = admin partout. Un compte de secours local dans admin_domain, dans le coffre, surveillé.
ScriptsIdentifiants d'application par usage : rôles nommés (les implications ne suivent pas), expiration, révocables ; jamais le mot de passe d'une personne.
Cycle de vieDésactiver avant de supprimer (user set --disable, domain set --disable) ; vérifier avec --effective ; revue trimestrielle des admin et des identifiants d'application.
Le test de cohérence : pour toute personne, « quel groupe, quel rôle, quelle cible » tient en une ligne de role assignment list --names. Un rôle direct ou plusieurs lignes : le découpage a dérivé.
