Neutron et OVN : qui décide, qui traduit, qui commute

Côté Neutron : neutron-server est l'API réseau : il reçoit la demande, l'enregistre dans MySQL (sa base de référence), puis la recopie dans OVN. RabbitMQ (file de messages d'OpenStack) ne sert presque plus avec OVN : tout passe par les bases OVN. Trajet : ① demande → ② MySQL → ③ Northbound → ④ ovn-northd traduit → Southbound → ⑤ lue par chaque nœud → ⑥ appliquée dans Open vSwitch → ⑦ « port actif » remonte à Nova.
Neutron sur Sunbeam · éléments OVN

Ce que fait concrètement chaque élément OVN

Exemple suivi : on crée la VM web1 (IP 10.0.0.11, réseau net-app, groupe sg-web : TCP 80) ; Nova la place sur compute-1. Une VM db1 tourne déjà sur compute-2.
ÉlémentC'est quoiCe qu'il fait concrètement pour web1
Northbound DBovn-central · port 6641PARTAGÉUne base de données : la liste du réseau voulu, sans aucun nœud physique. Elle ne fait rien seule : c'est un plan.neutron-server y écrit une ligne : « sur le réseau net-app, il existe un port 6d1f, MAC fa:16:3e:2b:11:01, IP 10.0.0.11, groupe sg-web ».
ovn-northdovn-central · 1 actifPARTAGÉUn programme traducteur, sans données. Il lit la Northbound et écrit dans la Southbound.Il transforme cette ligne en règles : « paquet entrant par le port de web1 : accepté seulement si MAC = …:01 et IP = 10.0.0.11 » ; « paquet vers la MAC …:01 → port de web1 » ; « vers web1 : TCP 80 accepté, le reste rejeté ». Il donne un numéro au réseau et au port.
Southbound DBovn-central · port 6642PARTAGÉUne base de données, la seule lue par les nœuds. Le tableau d'affichage commun : règles d'un côté, annuaire de l'autre.Elle contient les règles écrites par ovn-northd, et l'annuaire écrit par les nœuds : « compute-1 est joignable en 10.20.0.11 », « le port de web1 est sur compute-1 ».
ovn-relayovn-relay-k8sPARTAGÉUn répéteur de la Southbound.Les 200 hyperviseurs se connectent au relais, pas aux bases : il leur renvoie chaque changement et transmet leurs écritures à la Southbound.
ovn-controllerchaque hyperviseur et nœud networkLOCALLe programme OVN installé sur chaque nœud. Il applique localement ce qui est écrit dans la Southbound.Sur compute-1 : il voit apparaître tap6d1f (Nova vient de brancher web1) → écrit « port de web1 = chez moi » ; copie les règles du réseau net-app dans br-int ; ouvre un tunnel vers compute-2 ; répond au DHCP de web1 : « ton IP est 10.0.0.11 ».
Open vSwitch · br-intchaque nœudLOCALOpen vSwitch = le switch logiciel du nœud. br-int = le switch virtuel où toutes les VM du nœud sont branchées.web1 envoie un paquet à db1 : br-int vérifie la MAC source, voit que db1 est sur compute-2, emballe le paquet en Geneve (UDP 6081) vers 10.20.0.12. compute-2 déballe, applique le groupe de sécurité de db1, livre.
br-exnœuds network (passerelles)LOCALUn second switch virtuel, branché sur la carte réseau physique qui mène à l'extérieur (physnet1).db1 va sur Internet : sur network-1, le routeur remplace 10.0.0.12 par l'IP publique 203.0.113.2 (SNAT), puis br-ex pose le paquet sur la carte enp6s0. Idem en sens inverse pour l'IP flottante de web1.
