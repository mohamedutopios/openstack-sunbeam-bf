Architecture du lab Sunbeam

Ce que Lab-Sunbeam demande à Lab-Services

Les deux VM sont séparées, mais le cloud ne fonctionne pas sans Lab-Services. Lab-Sunbeam lui demande trois choses : trouver les adresses (DNS), sortir sur Internet pour les instances, et, pendant la journée sécurité, vérifier l’identité des personnes avec Keycloak.

Comment ils se parlent : trois parcours

Suivre une commande à travers le cloud est la meilleure façon de comprendre son architecture, et de savoir où chercher quand elle échoue.

Obtenir un jeton

openstack token issue
  1. Le client demande au DNS de Lab-Services l’adresse de cloud.lab.test : 192.168.56.201.
  2. Traefik public reçoit l’appel et le passe au pod keystone.
  3. Keystone vérifie le mot de passe dans MySQL, via keystone-mysql-router.
  4. Il renvoie un jeton, valable une heure, que le client joint à tous ses appels suivants.

Lancer une VM

openstack server create …
  1. nova-api reçoit la demande et fait valider le jeton par Keystone.
  2. nova-scheduler demande à Placement un hyperviseur qui a la place.
  3. Par RabbitMQ, nova-conductor confie la VM à nova-compute, sur la machine.
  4. nova-compute lit l’image dans Glance (Ceph) et demande un port à Neutron, qui le décrit à OVN.
  5. libvirt et KVM démarrent la VM ; ovn-controller branche son réseau ; l’agent de métadonnées lui donne sa clé SSH.

Joindre la VM depuis Windows

ssh ubuntu@192.168.57.1xx
  1. Windows envoie le paquet sur le réseau externe 192.168.57.0/24, à l’IP flottante de la VM.
  2. Il entre dans Lab-Sunbeam par la carte provider0.
  3. ovn-controller traduit l’IP flottante en adresse privée (routeur du projet) et applique le groupe de sécurité.
  4. Le paquet arrive dans la VM. Pour sortir sur Internet, la VM passe par le routeur, puis par la passerelle NAT de Lab-Services (192.168.57.2).

Ce qui se passe au démarrage

Les dépendances expliquent l’ordre de démarrage, et l’écran rouge de juju status des premières minutes :

  1. Lab-Services d’abord : sans son DNS, aucun service ne trouve les autres.
  2. Lab-Sunbeam : Kubernetes relance les pods, puis le contrôleur Juju et ses agents.
  3. MySQL démarre (maintenance « Starting mysqld »). Les routeurs qui ont essayé trop tôt passent en error : on les relance avec juju resolved.
  4. Les services retrouvent leur base : leurs tests de santé repassent au vert, et blocked devient active.
  5. Compter 10 à 15 minutes avant un cloud sain.
